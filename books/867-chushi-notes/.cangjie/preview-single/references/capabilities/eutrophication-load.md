## I — 方法论骨架

水华是结果，不是单一来源的诊断结论。
先把进入水体的营养盐按点源、农业等非点源和水体内部储存/释放拆开。
对外源负荷，要调查来源、监测浓度和流量，并换算为可比较的时段或年度负荷。
如果外源削减后水华仍持续，再检查底泥和孔隙水等内源释放，避免把内源问题误判成某个污水厂单独失效。
治理顺序通常是先控制外部输入，再针对证据充分的内源负荷处理，同时保留非点源缓冲和监测反馈。
判断每一步都要回到氮磷负荷、透明度、溶解氧和生态后果，而不是只观察水面颜色。

## A1 — 书中的应用

### 案例：长江流域综合治理
- **问题**：流域存在富营养化、高污染企业和农业/生活输入，单一措施难以解释水质变化。
- **方法论的使用**：资料同时列举点源治理、湖内负荷控制和非点源生态缓冲带。
- **结论**：先按来源和所在环节拆分负荷，再分别控制。
- **结果**：形成流域综合治理的分层答案。该内容是教材/讲义示例，资料没有证明为编写者亲历。

### 案例：水华形成链
- **问题**：大量营养盐进入水体后，为什么出现藻类繁殖、透明度下降和缺氧？
- **方法论的使用**：把营养盐输入、藻类增长、光照受限、溶解氧下降和水生生物死亡串联。
- **结论**：治理不能只打捞藻类，还要减少负荷并判断内源释放。
- **结果**：将现象题改写成负荷诊断题；这是资料示例而非个人案例。

## A2 — 触发场景

### 用户会在什么情境下需要这个 skill?

1. 用户问湖泊/水库为何反复水华，或污水截流后富营养化仍未缓解。
2. 题干出现氮磷、农业径流、污水厂、底泥释放、内源/外源负荷。
3. 用户要写富营养化成因、危害和治理的简答或论述答案。

### 语言信号（用户的话里出现这些就应激活）

- “富营养化 / 水华 / eutrophication / algal bloom”
- “外源负荷、内源负荷、底泥释放、氮磷总量”
- “截污后还在爆发、农业面源、入湖负荷”

### 与相邻 skill 的区分

- 与 `context-capacity` 的区别：本卡专门诊断营养盐来源和内外源顺序；容量卡处理任意污染物的情境化超载。
- 与 `monitoring-data` 的区别：本卡规定需要验证的负荷和内源证据；监测卡负责把问题转成完整采样与QA/QC流程。
- 与 `cross-media-tracing` 的区别：本卡聚焦水体富营养化负荷分区，不展开所有污染物的跨介质归趋。

## E — 可执行步骤

1. **确认富营养化表现和受体**
   - 列出藻类、水华、透明度、溶解氧、水生生物和水体功能目标。
   - **完成标准**：把“水华现象”与至少一个水质/生态后果对应起来。

2. **建立外源负荷清单**
   - 分点源、生活污水、工业排放、农业径流等非点源，监测浓度、流量和时段，核算氮磷负荷。
   - **完成标准**：能指出主要外源及其相对贡献，而不是只列来源名称。

3. **验证内源并排序治理**
   - 外源控制后检查底泥或孔隙水释放，再决定是否需要内源削减；同时设置缓冲带、施肥控制或截污措施。
   - **完成标准**：每项措施对应一个负荷来源，并有复测指标。
   - **判停条件**：若没有负荷或底泥证据，不直接断言内源主导，转为提出监测方案。

## B — 边界

### 不要在以下情况使用此 skill

- 用户只问BOD、COD或藻类术语定义，不涉及富营养化成因和治理。
- 题目是一般工业有机物污染，且没有氮磷或藻类线索。
- 用户要求现行水质标准或真实湖泊修复参数，资料无法替代规范和现场研究。

### 作者在书中警告的失败模式

- 只看到水面绿色就把责任归给污水厂。
- 只打捞藻类或处理末端，不核算外部氮磷输入。
- 把农业施肥、生活污水和底泥内源混成一个来源。

### 作者的盲点 / 时代局限

- 资料给出定性诊断顺序，未提供完整水动力—生态模型、负荷阈值或区域监测数据。
- “内源控制”具体措施的适用性需要按水体、底泥和现行生态治理规范核验。

### 容易混淆的邻近方法论

- 水华治理的外源/内源诊断不同于一般环境容量判断；前者是来源分解和治理排序，后者是负荷与情境容量比较。
