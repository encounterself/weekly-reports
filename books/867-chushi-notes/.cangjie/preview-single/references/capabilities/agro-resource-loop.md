## I — 方法论骨架

“资源化”不是把所有副产物就近倾倒，而是让物质在有能力接收它的系统内循环。
先核对粪污或农业副产物的数量、养分和潜在有害成分，再核对农田受纳容量、作物需求、季节、储存和运输距离。
如果近场农田不能消纳，必须寻找替代用户、能源回收、处理后储存或其他安全去向。
设计生态农业时，还要让种植、养殖、能源和土壤肥力互相补足，避免只有名义上的“循环”。
每个闭环都要检查规模、经济性、社会接受度、病原体/残留风险和雨季溢流风险。
循环利用的目标是减少资源浪费和污染，不是取消容量约束。

## A1 — 书中的应用

### 案例：畜禽粪污资源化
- **问题**：粪便具有肥料、饲料或能源价值，是否应全部就近施用？
- **方法论的使用**：资料要求先核对周边农田消纳能力、运输距离和季节，并配合清污分流、粪尿分离和组合技术。
- **结论**：资源化必须受受纳容量和物流条件约束。
- **结果**：把“有价值”转成可核算的闭环条件。该内容是教材/讲义示例，资料没有证明为编写者亲历。

### 案例：生态农业自维持系统
- **问题**：种植和养殖怎样形成生态农业而非简单拼接？
- **方法论的使用**：资料要求副产物再循环、种养互补、轮作/固氮和土壤肥力保持，并考虑规模和社会经济条件。
- **结论**：真正闭环要有物质回流、功能互补和长期可维持性。
- **结果**：形成生态农业设计的检查框架；这是来源示例而非个人实践。

## A2 — 触发场景

### 用户会在什么情境下需要这个 skill?

1. 用户问畜禽粪便、沼渣沼液或农业副产物能否直接还田/资源化。
2. 题干给出农田面积、养殖规模、季节、运输距离、养分饱和或替代用户。
3. 用户要设计生态农业、种养循环或农业废物综合利用方案。

### 语言信号（用户的话里出现这些就应激活）

- “粪污资源化 / manure / digestate / 农田消纳能力 / carrying capacity”
- “种养循环、生态农业、自维持闭环、沼渣沼液”
- “农田已经饱和、运输太远、雨季施肥、替代用户”

### 与相邻 skill 的区分

- 与 `context-capacity` 的区别：本卡把容量、物流和季节约束落实到农业物质闭环；容量卡是更一般的污染超载判断。
- 与 `preventive-material-flow` 的区别：本卡专门处理农业接收端和种养互补；物料流卡按一般企业/区域的输入到残余排序。
- 与 `pesticide-risk` 的区别：农药卡管理施药和残留，本卡管理粪污/副产物的安全去向与闭环。

## E — 可执行步骤

1. **核算来源和受纳系统**
   - 列出粪污数量、养分/残留风险、农田面积、作物需求、已有负荷、季节、储存和运输距离。
   - **完成标准**：能判断近场农田是可接收、接近上限还是明显超载。

2. **设计真实闭环和备选去向**
   - 按清污分流、粪尿分离、肥料/能源/材料利用和种养互补设计物质回流；容量不足时安排储存或替代用户。
   - **完成标准**：每种副产物都有安全去向，且闭环不是只在名义上成立。
   - **判停条件**：若没有接收容量、残留安全或雨季储存证据，不得建议直接还田，转为补充调查和风险控制。

3. **验证可维持性**
   - 检查成本、规模、运输、病原体/抗生素残留、土壤水体风险和社会接受度，并用监测反馈调整。
   - **完成标准**：同时给出环境、经济和运行约束下的可持续结论。

## B — 边界

### 不要在以下情况使用此 skill

- 用户只问循环经济或生态农业的名词定义。
- 用户要求具体粪污施用量、病原体处理参数或现行还田标准。
- 题目没有农业、养殖、副产物或受纳容量情境，只讨论一般工业物料流。

### 作者在书中警告的失败模式

- 因为粪污有肥料价值，就忽略农田消纳能力、季节和运输。
- 把“资源化”当成无限施肥，导致养分、病原体或抗生素进入水土环境。
- 设计只有一条近场去向的闭环，不准备储存、替代用户和溢流风险措施。

### 作者的盲点 / 时代局限

- 资料没有提供具体养分平衡、病原体/抗生素处理参数和现行农业利用标准。
- 真实闭环需要区域数据、检测和经济核算；本卡主要用于考研情境推理。

### 容易混淆的邻近方法论

- 资源化的“回流”必须先通过容量与安全检查；它不等于废物自动无害，也不等于普通回收率最大化。
